        <div class="mat-section" id="mat-p1">
          <div class="section-head">
            <h3>1. Modelo de utilidad: definición y requisitos</h3>
            <div class="badges">
              <span class="badge fuente">A1</span>
              <span class="badge pareto">Pareto</span>
              <span class="badge cae">Cae siempre</span>
            </div>
          </div>
          <p class="enunciado-q">¿Qué es el modelo de utilidad y qué elementos exige su registro?</p>
          <details>
            <summary>Ver respuesta</summary>
            <div class="detail-content">
              <p><b>(a) Definición:</b></p>
              <p>El modelo de utilidad protege una nueva forma o disposición introducida en herramientas, instrumentos, utensilios, dispositivos u objetos ya conocidos, cuando esa novedad importe una mejor utilización en la función a la que están destinados (art. 56, Ley 24.481). No protege el producto en sí, sino la nueva utilidad agregada sobre algo preexistente.</p>
              <p style="margin-top:10px;"><b>(b) Requisitos para su registro:</b></p>
              <ol>
                <li><b>Novedad relativa:</b> referida únicamente a la utilidad puntual agregada (no al producto de base).</li>
                <li><b>Aplicación industrial:</b> posibilidad de reproducción a gran escala.</li>
                <li><b>Ausencia de actividad inventiva como requisito exigido:</b> a diferencia de la patente, no hace falta acreditarla.</li>
              </ol>
            </div>
          </details>
          <details class="error-detail">
            <summary>Ver error típico</summary>
            <div class="detail-content"><b>❌ Error típico:</b> Exigir actividad inventiva para el modelo de utilidad, cuando es precisamente el elemento que lo distingue —por ausencia— de la patente.</div>
          </details>
        </div>

        <div class="mat-section" id="mat-p2">
          <div class="section-head">
            <h3>2. Modelo de utilidad vs. modelo/diseño industrial</h3>
            <div class="badges">
              <span class="badge fuente">A1, A2</span>
              <span class="badge trampa">Trampa</span>
              <span class="badge cae">Cae siempre</span>
            </div>
          </div>
          <p class="enunciado-q">¿Cuál es la diferencia entre modelo de utilidad y modelo/diseño industrial?</p>
          <details>
            <summary>Ver respuesta</summary>
            <div class="detail-content">
              <p>Se trata de institutos que protegen aspectos distintos de un mismo producto: el modelo de utilidad protege una función nueva, mientras que el modelo y el diseño industrial protegen el carácter ornamental o estético.</p>
              <table>
                <thead><tr><th></th><th>Modelo de utilidad</th><th>Modelo industrial</th><th>Diseño industrial</th></tr></thead>
                <tbody>
                  <tr><td>Objeto protegido</td><td>Nueva utilidad/función</td><td>Forma ornamental 3D</td><td>Forma ornamental 2D</td></tr>
                  <tr><td>Norma</td><td>Art. 56, Ley 24.481</td><td>Decreto de 1963</td><td>Decreto de 1963</td></tr>
                  <tr><td>Plazo</td><td>10 años improrrogables</td><td>Hasta 15 años (5+5+5)</td><td>Hasta 15 años (5+5+5)</td></tr>
                  <tr><td>Ejemplo de clase</td><td>Spray exprimidor, accesorios Victorinox</td><td>Envase de perfume</td><td>Estampado textil (Louis Vuitton)</td></tr>
                </tbody>
              </table>
            </div>
          </details>
          <details class="error-detail">
            <summary>Ver error típico</summary>
            <div class="detail-content"><b>❌ Error típico:</b> Usar "modelo de utilidad" y "modelo industrial" como sinónimos, cuando protegen bienes jurídicos distintos —función versus estética—. Un caso límite discutido en clase es el tetrabrik con tapita: la docente lo encuadró más cerca de diseño porque no cambia la utilidad del producto, solo lo hace más práctico.</div>
          </details>
        </div>

        <div class="mat-section" id="mat-p3">
          <div class="section-head">
            <h3>3. Modelo de utilidad vs. patente</h3>
            <div class="badges">
              <span class="badge fuente">A1, S1</span>
              <span class="badge pareto">Pareto</span>
            </div>
          </div>
          <p class="enunciado-q">¿Qué diferencia al modelo de utilidad de la patente?</p>
          <details>
            <summary>Ver respuesta</summary>
            <div class="detail-content">
              <p>Comparten el objeto legal (regulados ambos por la Ley 24.481) pero difieren en sus requisitos:</p>
              <ol>
                <li><b>Novedad:</b> en la patente debe ser absoluta (creación desde cero); en el modelo de utilidad, relativa (solo la utilidad agregada debe ser nueva).</li>
                <li><b>Actividad inventiva:</b> exigida en la patente (el resultado no debe alcanzarse por mera aplicación lógica del estado de la técnica); no exigida en el modelo de utilidad.</li>
                <li><b>Aplicación industrial:</b> exigida en ambos por igual.</li>
              </ol>
              <p style="margin-top:10px;">Por el art. 56, 2º párrafo, de la Ley 24.481, quien ya tiene patente sobre un producto no puede además obtener un certificado de modelo de utilidad sobre ese mismo objeto.</p>
            </div>
          </details>
          <details class="error-detail">
            <summary>Ver error típico</summary>
            <div class="detail-content"><b>❌ Error típico:</b> Creer que pueden acumularse patente y modelo de utilidad sobre el mismo producto, cuando la ley lo prohíbe expresamente.</div>
          </details>
        </div>

        <div class="mat-section" id="mat-p4">
          <div class="section-head">
            <h3>4. Plazo de vigencia del modelo de utilidad</h3>
            <div class="badges">
              <span class="badge fuente">A1</span>
              <span class="badge trampa">Trampa</span>
            </div>
          </div>
          <p class="enunciado-q">¿Desde qué fecha corre el plazo de vigencia del modelo de utilidad?</p>
          <details>
            <summary>Ver respuesta</summary>
            <div class="detail-content">
              <p>El plazo de <b>10 años improrrogables</b> corre desde la fecha de <b>presentación</b> de la solicitud ante el INPI, no desde la fecha en que el organismo resuelve otorgar el certificado.</p>
              <p style="margin-top:10px;">En el ejemplo mostrado en clase, la presentación fue el 28/05/2019, la resolución el 20/12/2021, y el vencimiento quedó fijado igualmente en el 28/05/2029 —es decir, a los 10 años de la presentación, no de la resolución—.</p>
            </div>
          </details>
          <details class="error-detail">
            <summary>Ver error típico</summary>
            <div class="detail-content"><b>❌ Error típico:</b> Calcular el vencimiento desde la fecha del certificado otorgado por el INPI, ignorando que el trámite puede demorar años y que ese tiempo corre en contra del titular.</div>
          </details>
        </div>

        <div class="mat-section" id="mat-p5">
          <div class="section-head">
            <h3>5. Forma tridimensional: marca vs. modelo industrial</h3>
            <div class="badges">
              <span class="badge fuente">A2, A3</span>
              <span class="badge pareto">Pareto</span>
            </div>
          </div>
          <p class="enunciado-q">¿Se puede proteger la misma forma tridimensional como marca y como modelo industrial?</p>
          <details>
            <summary>Ver respuesta</summary>
            <div class="detail-content">
              <p><b>(a) Sí</b>, porque cada instituto protege un aspecto distinto de esa forma:</p>
              <ol>
                <li>Como <b>marca tridimensional</b>, se protege la asociación entre esa forma y el origen comercial del producto (que el consumidor identifique la forma con una marca determinada).</li>
                <li>Como <b>modelo industrial</b>, se protege la ornamentalidad de esa forma, con independencia de que además funcione como signo distintivo.</li>
              </ol>
              <p style="margin-top:10px;"><b>(b) Límite común:</b> la forma no sea la necesaria para que el producto cumpla su función (por ejemplo, que una pelota sea redonda); en ese caso, tampoco es registrable como marca por carecer de capacidad distintiva.</p>
              <table>
                <thead><tr><th></th><th>Marca tridimensional</th><th>Modelo industrial</th></tr></thead>
                <tbody>
                  <tr><td>Plazo</td><td>10 años, renovable indefinidamente</td><td>Hasta 15 años, improrrogable</td></tr>
                  <tr><td>Ejemplo de clase</td><td>Envase "One Million" (barrita de oro)</td><td>Mismo envase, en su faz ornamental</td></tr>
                </tbody>
              </table>
            </div>
          </details>
          <details class="error-detail">
            <summary>Ver error típico</summary>
            <div class="detail-content"><b>❌ Error típico:</b> Asumir que, vencido el modelo industrial (15 años), también se pierde la marca; en realidad la marca sigue vigente si fue renovada, porque protege algo distinto.</div>
          </details>
        </div>

        <div class="mat-section" id="mat-p6">
          <div class="section-head">
            <h3>6. Secreto comercial</h3>
            <div class="badges">
              <span class="badge fuente">O3</span>
              <span class="badge cae">Cae siempre</span>
            </div>
          </div>
          <p class="enunciado-q">¿Qué es el secreto comercial y qué ocurre si se revela?</p>
          <details>
            <summary>Ver respuesta</summary>
            <div class="detail-content">
              <p><b>(a) Definición:</b></p>
              <p>El secreto comercial protege información valiosa para una empresa —una fórmula, un procedimiento— que no se registra ante ningún organismo (no es patente, ni marca, ni modelo de utilidad, ni diseño/modelo industrial), sino que se resguarda mediante confidencialidad, típicamente a través de un acuerdo de confidencialidad (NDA).</p>
              <p style="margin-top:10px;"><b>(b) Plazo:</b></p>
              <p>A diferencia de los demás institutos vistos en la clase, no tiene plazo de caducidad: puede sostenerse indefinidamente mientras se preserve el secreto de hecho.</p>
              <p style="margin-top:10px;"><b>(c) Si se revela:</b></p>
              <p>La consecuencia indicada en clase es <b>responsabilidad penal</b> —no meramente civil—, lo que lo distingue de un incumplimiento contractual ordinario.</p>
            </div>
          </details>
          <details class="error-detail">
            <summary>Ver error típico</summary>
            <div class="detail-content"><b>❌ Error típico:</b> Suponer que existe algún registro o plazo de vencimiento para el secreto comercial, cuando su protección depende exclusivamente de mantenerlo confidencial.</div>
          </details>
        </div>

        <div class="mat-section" id="mat-p7">
          <div class="section-head">
            <h3>7. Acumulación de protecciones sobre un mismo producto</h3>
            <div class="badges">
              <span class="badge fuente">O4, A1</span>
              <span class="badge pareto">Pareto</span>
            </div>
          </div>
          <p class="enunciado-q">¿Puede acumularse la protección sobre un mismo producto y qué límite tiene esa acumulación?</p>
          <details>
            <summary>Ver respuesta</summary>
            <div class="detail-content">
              <p><b>(a) En principio sí:</b></p>
              <p>Un mismo producto puede protegerse simultáneamente por varias vías de propiedad industrial (marca, modelo de utilidad, modelo/diseño industrial), porque cada una protege un aspecto jurídico distinto y cada trámite se presenta por separado ante la dirección correspondiente del INPI. La única incompatibilidad expresa vista en clase es patente y modelo de utilidad sobre el mismo objeto (art. 56, 2º párr., Ley 24.481).</p>
              <p style="margin-top:10px;"><b>(b) Límite:</b></p>
              <p>Esa acumulación tiene un límite: ningún instituto de propiedad industrial habilita apropiarse de derechos de un tercero. Que un objeto reúna en abstracto los requisitos de un modelo o de una marca no autoriza su explotación si su contenido pertenece a otro (caso de las tazas con personajes de Disney).</p>
            </div>
          </details>
          <details class="error-detail">
            <summary>Ver error típico</summary>
            <div class="detail-content"><b>❌ Error típico:</b> Creer que una sola presentación cubre marca, modelo de utilidad y modelo industrial a la vez, cuando cada instituto exige trámite separado, con requisitos y costos propios; o bien creer que la elaboración artesanal de un producto exime de infringir derechos de terceros.</div>
          </details>
        </div>

        <div class="mat-section" id="mat-p8">
          <div class="section-head">
            <h3>8. Clasificación de Locarno vs. Niza</h3>
            <div class="badges">
              <span class="badge fuente">S4</span>
              <span class="badge trampa">Trampa</span>
            </div>
          </div>
          <p class="enunciado-q">¿En qué se diferencia la clasificación de Locarno de la clasificación de Niza?</p>
          <details>
            <summary>Ver respuesta</summary>
            <div class="detail-content">
              <p><b>(a) Clasificación de Niza:</b></p>
              <p>Usada para <b>marcas</b>, distingue clases de productos (1 a 34) y de servicios (35 a 45).</p>
              <p style="margin-top:10px;"><b>(b) Clasificación de Locarno:</b></p>
              <p>Usada para <b>diseños y modelos industriales</b>, está organizada por rubro (por ejemplo, agroquímicos) y comprende únicamente productos, sin categoría de servicios.</p>
            </div>
          </details>
          <details class="error-detail">
            <summary>Ver error típico</summary>
            <div class="detail-content"><b>❌ Error típico:</b> Aplicar la lógica de clases de Niza —con su distinción entre productos y servicios— al momento de clasificar un diseño o modelo industrial bajo Locarno.</div>
          </details>
        </div>

        <div class="mat-section" id="mat-int">
          <div class="section-head">
            <h3>Integradora · La botella de Martina</h3>
            <div class="badges">
              <span class="badge cae">Cae siempre</span>
            </div>
          </div>
          <div class="contexto-caso">
            Martina diseña una botella de agua reutilizable que incorpora una curva central que facilita agarrarla mejor y un mecanismo que permite plegarla para ocupar menos espacio. Además, decide decorar la superficie con un estampado geométrico distintivo. Antes de presentar los trámites, un colega le muestra que ese mismo estampado ya fue registrado como diseño industrial por otra empresa, sin que Martina lo supiera al momento de crearlo.
          </div>
          <p class="enunciado-q">(a) ¿Qué figura de propiedad industrial protege la forma ergonómica y plegable de la botella, y por qué corresponde esa figura y no otra?</p>
          <p class="enunciado-q">(b) ¿Puede Martina proteger en un mismo trámite tanto la funcionalidad de la botella como el estampado ornamental, o necesita presentaciones separadas?</p>
          <p class="enunciado-q">(c) Dado que el estampado que Martina quiere usar ya está registrado por un tercero, ¿puede igualmente registrarlo o explotarlo como propio?</p>
          <details>
            <summary>Ver resolución completa</summary>
            <div class="detail-content">
              <p><b>(a)</b> La forma ergonómica y plegable corresponde a un <b>modelo de utilidad</b>, porque se trata de una nueva función —mejor agarre, menor volumen— agregada a un producto ya conocido (una botella), sin que se requiera acreditar actividad inventiva ni novedad absoluta del producto en sí, sino solo de esa utilidad puntual.</p>
              <p style="margin-top:10px;"><b>(b)</b> No. Cada instituto exige un <b>trámite separado</b> ante la dirección correspondiente del INPI, con requisitos y costos propios: el modelo de utilidad va por un lado y, si Martina quisiera registrar un estampado propio como diseño industrial, sería una presentación distinta.</p>
              <p style="margin-top:10px;"><b>(c)</b> No. Aun cuando el estampado cumpliera en abstracto los requisitos de originalidad y novedad para Martina, no puede registrarlo ni explotarlo porque ya pertenece a un tercero: acumular protecciones sobre un producto no habilita apropiarse de derechos ajenos, tal como se vio con el caso de las tazas con personajes de Disney.</p>
            </div>
          </details>
          <details class="error-detail">
            <summary>Ver error típico</summary>
            <div class="detail-content"><b>⚠ Error típico:</b> Un alumno que memorizó los institutos por separado puede resolver correctamente (a) y (b), pero fallar en (c) al no conectar el límite del sistema de acumulación con el caso concreto, tratando la titularidad de terceros como un problema ajeno a la propiedad industrial.</div>
          </details>
        </div>

        <div class="mat-section" id="mat-c1">
          <div class="section-head">
            <h3>Caso 1 · El nuevo accesorio de la multiherramienta</h3>
            <div class="badges">
              <span class="badge fuente">Simple</span>
              <span class="badge fuente">O1, S1</span>
              <span class="badge fuente">A1</span>
            </div>
          </div>
          <div class="contexto-caso">
            Diego fabrica multiherramientas tipo navaja suiza. A su modelo básico, ya conocido en el mercado, le agrega un destapador de botellas integrado que no existía en ese producto. Diego quiere saber si puede proteger esa incorporación y, si es así, bajo qué figura.
          </div>
          <details>
            <summary>Ver resolución</summary>
            <div class="detail-content">
              <p><b>Figura jurídica en juego:</b> Modelo de utilidad.</p>
              <p style="margin-top:10px;"><b>Razonamiento:</b></p>
              <ol>
                <li>El producto de base (la multiherramienta) ya es conocido; lo que Diego aporta no es un objeto nuevo desde cero.</li>
                <li>Lo que agrega es una nueva utilidad —el destapador— sobre ese producto conocido, que mejora su función.</li>
                <li>No se requiere actividad inventiva, a diferencia de la patente; basta con que esa utilidad puntual sea novedosa y tenga aplicación industrial.</li>
                <li>Si Diego ya tuviera otros accesorios registrados sobre la misma multiherramienta, este nuevo accesorio se tramita por separado, como una utilidad distinta.</li>
              </ol>
              <p style="margin-top:10px;"><b>Respuesta:</b> Diego puede proteger el destapador como modelo de utilidad, en trámite independiente, por 10 años improrrogables contados desde la fecha de presentación de la solicitud.</p>
            </div>
          </details>

            <summary>Ver error típico</summary>
            <div class="detail-content"><b>❌ Error típico:</b> Exigir que Diego demuestre actividad inventiva o que el conjunto de la multiherramienta sea enteramente nuevo, cuando el modelo de utilidad solo exige novedad de la utilidad agregada.</div>

        <div class="mat-section" id="mat-c2">
          <div class="section-head">
            <h3>Caso 2 · El envase con tapa práctica</h3>
            <div class="badges">
              <span class="badge trampa">Trampa</span>
              <span class="badge fuente">O1, O2, T1, T5</span>
              <span class="badge fuente">A1, A2</span>
            </div>
          </div>
          <div class="contexto-caso">
            Una empresa de lácteos rediseña su envase tradicional: en vez de tener que cortar una esquina para abrirlo, le incorpora una tapa rosca en la parte superior. La empresa consulta a su abogado si debe registrar esto como modelo de utilidad, porque "ahora es mucho más fácil de abrir y cerrar".
          </div>
          <details>
            <summary>Ver resolución</summary>
            <div class="detail-content">
              <p><b>Figura jurídica en juego:</b> Caso límite entre modelo de utilidad y diseño/modelo industrial; conforme el criterio de la docente, se inclina hacia diseño industrial.</p>
              <p style="margin-top:10px;"><b>Razonamiento:</b></p>
              <ol>
                <li>Hay que preguntarse si la tapa cambia la función esencial del envase (contener y despachar el producto) o solo la hace más práctica sin alterar esa función.</li>
                <li>Según el criterio expuesto en clase para un caso análogo (el tetrabrik con tapita), agregar practicidad sin modificar la utilidad del producto se acerca más al diseño industrial que al modelo de utilidad.</li>
                <li>Esto no es una regla automática: si la tapa permitiera, por ejemplo, dosificar el líquido de una manera que antes era imposible, el análisis podría inclinarse hacia modelo de utilidad, porque ahí sí habría una nueva función.</li>
                <li>Con los datos del enunciado (solo mayor comodidad de apertura), el caso se resuelve como diseño, no como modelo de utilidad.</li>
              </ol>
              <p style="margin-top:10px;"><b>Respuesta:</b> No corresponde automáticamente modelo de utilidad; conforme el criterio de la clase, se trata de un caso más cercano al diseño industrial, salvo que se acredite que la tapa aporta una utilidad funcional nueva y no solo mayor practicidad.</p>
              <p style="margin-top:10px; font-style:italic; color:var(--warn);"><b>Nota:</b> La docente calificó este tipo de caso como "discutible entre una figura y otra" — conviene dejarlo señalado como zona gris y no como regla cerrada si lo vas a usar para preparar una respuesta de examen.</p>
            </div>
          </details>
          <details class="error-detail">
            <summary>Ver error típico</summary>
            <div class="detail-content"><b>❌ Error típico:</b> Asumir que cualquier mejora práctica en un envase es, por definición, un modelo de utilidad, sin distinguir entre "nueva función" y "mayor comodidad de uso".</div>
          </details>

        <div class="mat-section" id="mat-c3">
          <div class="section-head">
            <h3>Caso 3 · El frasco de perfume "Lumière"</h3>
            <div class="badges">
              <span class="badge fuente">Complejo</span>
              <span class="badge fuente">O2, O4, S2, D3</span>
              <span class="badge fuente">A2, A3</span>
            </div>
          </div>
          <div class="contexto-caso">
            La empresa Lumière diseña un frasco de perfume con forma de estrella dorada, absolutamente distintivo dentro del mercado. Ya registró esa forma como marca tridimensional. Ahora su asesora legal le sugiere registrar también la forma del frasco como modelo industrial. El gerente de Lumière pregunta si eso no sería "duplicar" una protección que ya tienen.
          </div>
          <details>
            <summary>Ver resolución</summary>
            <div class="detail-content">
              <p><b>Figura jurídica en juego:</b> Acumulación de marca tridimensional y modelo industrial sobre el mismo objeto.</p>
              <p style="margin-top:10px;"><b>Razonamiento:</b></p>
              <ol>
                <li>La marca tridimensional protege que el consumidor asocie esa forma de estrella dorada con el origen comercial Lumière; es un derecho renovable indefinidamente cada 10 años.</li>
                <li>El modelo industrial protegería la ornamentalidad de esa misma forma en sí, con independencia de si el consumidor la asocia o no con una marca; su plazo máximo es de 15 años (5+5+5), improrrogable.</li>
                <li>No hay incompatibilidad entre ambas figuras porque cada una protege un aspecto jurídico distinto: origen comercial en un caso, estética en el otro.</li>
                <li>La consecuencia práctica de registrar ambas surge recién al vencimiento del modelo industrial: pasados los 15 años, un tercero podría fabricar frascos con esa misma forma ornamental, pero no podría usarlos como marca de sus propios productos si la marca de Lumière sigue vigente y renovada.</li>
              </ol>
              <p style="margin-top:10px;"><b>Respuesta:</b> No se trata de una duplicación inútil: registrar ambas figuras amplía la protección de Lumière, porque cubre dos riesgos distintos (imitación de la forma como tal, y confusión de origen comercial), con plazos y alcances diferentes.</p>
            </div>
          </details>
          <details class="error-detail">
            <summary>Ver error típico</summary>
            <div class="detail-content"><b>❌ Error típico:</b> Creer que, al vencer el modelo industrial, también se pierde la marca tridimensional, ignorando que son derechos independientes que protegen bienes jurídicos distintos.</div>
          </details>
          <p class="link-rel">🔗 Relacionado con P5 del cuestionario.</p>
          <div class="contrafactico">
            <b>Sub-escenario contrafáctico:</b> Supongamos que la forma de estrella del frasco no fuera meramente distintiva, sino la única forma posible para que el producto funcionara como perfume (por ejemplo, si fuera indispensable para el mecanismo de vaporización). ¿Podría igualmente registrarse como marca tridimensional?<br><br>
            <b>Resolución contrafáctica:</b> No. Si la forma fuera necesaria para que el producto cumpla su función, carecería de capacidad distintiva a los fines marcarios —el mismo límite señalado en clase para el caso de la pelota, que necesariamente debe ser redonda para rodar—. En ese escenario, Lumière podría eventualmente proteger esa forma como modelo industrial (si reúne originalidad y ornamentalidad) o, si existiera una función técnica nueva, como modelo de utilidad, pero no como marca.
          </div>

const STORAGE_KEY = "comercial_clase5_progress";

const state = {
  queue: [],
  current: null,
  phase: "recall",
  progress: {},
  sessionStats: { ok: 0, err: 0 },
  mode: "full",
  viewedCount: 0,
  flashcards: {
    index: 0,
    revealed: false,
    order: []
  }
};

function saveProgress() {
  try {
    const data = { progress: state.progress, sessionStats: state.sessionStats };
    localStorage.setItem(STORAGE_KEY, JSON.stringify(data));
  } catch (e) {}
}

function loadProgress() {
  try {
    const raw = localStorage.getItem(STORAGE_KEY);
    if (!raw) return false;
    const data = JSON.parse(raw);
    if (data && data.progress) state.progress = data.progress;
    if (data && data.sessionStats) state.sessionStats = data.sessionStats;
    return true;
  } catch (e) { return false; }
}

function clearProgress() {
  try { localStorage.removeItem(STORAGE_KEY); } catch (e) {}
}

function $(sel) { return document.querySelector(sel); }
function showScreen(id) {
  document.querySelectorAll(".screen").forEach(s => s.classList.remove("active"));
  document.getElementById(id).classList.add("active");
  window.scrollTo({ top: 0, behavior: "smooth" });
}

function getProgress(qid) {
  if (!state.progress[qid]) state.progress[qid] = { okCount: 0, errCount: 0, mastered: false, attempts: 0 };
  return state.progress[qid];
}
function isMastered(qid) { return getProgress(qid).mastered; }

function buildQueue(mode) {
  let pool = mode === "weak" ? QUESTIONS.filter(q => !isMastered(q.id)) : [...QUESTIONS];
  const order = { critico: 0, alto: 1, medio: 2 };
  pool.sort((a,b) => order[a.priority] - order[b.priority]);
  const groups = { critico: [], alto: [], medio: [] };
  pool.forEach(q => groups[q.priority].push(q));
  Object.values(groups).forEach(g => shuffle(g));
  state.queue = [...groups.critico, ...groups.alto, ...groups.medio];
  state.viewedCount = 0;
}
function shuffle(arr) {
  for (let i = arr.length - 1; i > 0; i--) {
    const j = Math.floor(Math.random() * (i + 1));
    [arr[i], arr[j]] = [arr[j], arr[i]];
  }
}
function reinsertLater(q) {
  const insertAt = Math.min(state.queue.length, 2 + Math.floor(Math.random() * 3));
  state.queue.splice(insertAt, 0, q);
}
function countMastered() { return QUESTIONS.filter(q => isMastered(q.id)).length; }

function hasWeakQuestions() {
  return QUESTIONS.some(q => !isMastered(q.id) && getProgress(q.id).attempts > 0);
}

function updateReviewOnlyButtonVisibility() {
  const btn = $("#btn-review-only");
  if (hasWeakQuestions()) btn.classList.remove("hidden");
  else btn.classList.add("hidden");
}

function renderQuestion() {
  if (state.queue.length === 0) { renderSummary(); return; }
  state.current = state.queue.shift();
  state.phase = "recall";
  state.viewedCount++;
  updateProgressBar();
  drawQuestion();
}

function updateProgressBar() {
  const total = QUESTIONS.length;
  const mastered = countMastered();
  const currentNum = Math.min(state.viewedCount, total);
  $("#stat-current").textContent = currentNum;
  $("#stat-total").textContent = total;
  $("#stat-mastered").textContent = mastered;
  $("#progress-fill").style.width = ((mastered / total) * 100) + "%";
}

function drawQuestion() {
  const q = state.current;
  const p = getProgress(q.id);
  const container = $("#question-container");
  let prioridadLabel = "";
  if (q.priority === "critico") prioridadLabel = '<span class="priority critico">Crítico</span>';
  else if (q.priority === "alto") prioridadLabel = '<span class="priority alto">Alto</span>';
  else prioridadLabel = '<span class="priority medio">Medio</span>';
  const counterBadge = `
    <span class="counter-badge ${p.okCount>0?'ok':''}">✓ ${p.okCount}/2</span>
    ${p.errCount>0 ? `<span class="counter-badge err">✗ ${p.errCount}</span>` : ""}
  `;
  container.innerHTML = `
    <div class="card">
      <div class="tag-row">
        <span class="tag">${q.id} · ${q.topic}</span>
        ${prioridadLabel}
        ${counterBadge}
      </div>
      ${q.contexto ? `<div class="contexto">${q.contexto}</div>` : ""}
      <h3>${q.enunciado}</h3>
      <div id="phase-content"></div>
    </div>
  `;
  if (state.phase === "recall") drawRecallPhase(q);
  else if (state.phase === "feedback") drawFeedbackPhase(q);
  else if (state.phase === "mc") drawMCPhase(q);
}

function drawRecallPhase(q) {
  const pc = $("#phase-content");
  pc.innerHTML = `
    <span class="phase-label">Fase 1 · Recall libre</span>
    <div class="recall-area">
      <textarea id="recall-input" placeholder="Escribí lo que recordás de la respuesta. No importa la extensión: el esfuerzo de recordar es lo que fija el contenido."></textarea>
      <div class="recall-hint"><b>Pista:</b> ${q.pista}</div>
    </div>
    <div class="btn-row">
      <button class="btn" id="btn-show-answer">Ver respuesta modelo</button>
      <button class="btn secondary" id="btn-skip">Saltar pregunta</button>
    </div>
  `;
  $("#btn-show-answer").addEventListener("click", () => { state.phase = "feedback"; drawQuestion(); });
  $("#btn-skip").addEventListener("click", () => { reinsertLater(q); renderQuestion(); });
}

function drawFeedbackPhase(q) {
  const pc = $("#phase-content");
  pc.innerHTML = `
    <span class="phase-label">Fase 2 · Respuesta modelo</span>
    <div class="feedback">
      <h4>Respuesta correcta</h4>
      <div class="bloque">${q.respuestaLibre.replace(/\n/g, "<br>")}</div>
      <h4>Explicación</h4>
      <p>${q.explicacion}</p>
      <h4>Error típico — marcá bien este límite</h4>

    </div>
    <div class="btn-row">
      <button class="btn" id="btn-to-mc">Continuar → Refuerzo con opciones</button>
    </div>
  `;
  $("#btn-to-mc").addEventListener("click", () => { state.phase = "mc"; drawQuestion(); });
}

function drawMCPhase(q) {
  const pc = $("#phase-content");
  const opcionesIdx = q.opciones.map((_, i) => i);
  shuffle(opcionesIdx);
  let optsHtml = opcionesIdx.map((realIdx, displayIdx) => {
    const letter = String.fromCharCode(65 + displayIdx);
    return `<li data-real="${realIdx}"><span class="letter">${letter}</span>${q.opciones[realIdx]}</li>`;
  }).join("");
  pc.innerHTML = `
    <span class="phase-label">Fase 3 · Refuerzo con opciones</span>
    <ul class="options" id="options-list">${optsHtml}</ul>
    <div id="mc-feedback"></div>
  `;
  pc.querySelectorAll("#options-list li").forEach(li => {
    li.addEventListener("click", () => handleMCAnswer(q, li));
  });
}

function handleMCAnswer(q, liClicked) {
  const realIdx = parseInt(liClicked.getAttribute("data-real"));
  const isCorrect = realIdx === q.correcta;
  const p = getProgress(q.id);
  p.attempts++;
  document.querySelectorAll("#options-list li").forEach(li => {
    li.classList.add("disabled");
    const r = parseInt(li.getAttribute("data-real"));
    if (r === q.correcta) li.classList.add("correct");
    else if (li === liClicked) li.classList.add("wrong");
  });
  if (isCorrect) {
    p.okCount++;
    state.sessionStats.ok++;
    if (p.okCount >= 2) p.mastered = true;
  } else {
    p.errCount++;
    state.sessionStats.err++;
    p.okCount = 0;
  }
  saveProgress();
  updateProgressBar();
  const fb = $("#mc-feedback");
  const verdict = isCorrect
    ? (p.mastered ? "✓ DOMINADA — dos aciertos consecutivos" : "✓ Correcto — necesitás un acierto más para dominarla")
    : "✗ Incorrecto — la pregunta volverá a aparecer más adelante";
  fb.innerHTML = `
    <div class="feedback ${isCorrect ? 'ok' : 'err'}">
      <div class="veredicto">${verdict}</div>
      ${!isCorrect ? `
        <h4>Respuesta correcta</h4>
        <p>${q.respuestaLibre.replace(/\n/g, "<br>")}</p>
        <h4>Error típico</h4>
        <div class="error-tipico"><b>⚠</b> ${q.errorTipico}</div>
      ` : ""}
    </div>
    <div class="btn-row">
      <button class="btn" id="btn-next">Continuar →</button>
    </div>
  `;
  if (!isCorrect && !p.mastered) reinsertLater(q);
  $("#btn-next").addEventListener("click", () => {
    if (state.queue.length === 0) renderSummary();
    else renderQuestion();
  });
}

function renderSummary() {
  const mastered = QUESTIONS.filter(q => isMastered(q.id));
  const weak = QUESTIONS.filter(q => !isMastered(q.id) && getProgress(q.id).attempts > 0);
  const untouched = QUESTIONS.filter(q => getProgress(q.id).attempts === 0);
  $("#sum-mastered").textContent = mastered.length;
  $("#sum-weak").textContent = weak.length + untouched.length;
  $("#sum-ok").textContent = state.sessionStats.ok;
  $("#sum-err").textContent = state.sessionStats.err;
  const listWeak = $("#list-weak");
  const allWeak = [...weak, ...untouched];
  if (allWeak.length === 0) {
    listWeak.innerHTML = '<li style="border-left-color:var(--ok); background:var(--ok-bg); color:var(--ok);">No hay temas débiles. ¡Sesión perfecta!</li>';
  } else {
    listWeak.innerHTML = allWeak.map(q => {
      const p = getProgress(q.id);
      const estado = p.attempts === 0 ? "no intentada" : `${p.errCount} error(es)`;
      return `<li><span class="q-id">${q.id}</span><b>${q.topic}</b> <span style="color:var(--text-dim); font-size:12px; margin-left:6px;">(${estado})</span></li>`;
    }).join("");
  }
  const listMastered = $("#list-mastered");
  if (mastered.length === 0) {
    listMastered.innerHTML = '<li style="color:var(--text-dim); background:var(--bg-3); border-left-color:var(--border);">Todavía no dominaste ninguna pregunta.</li>';
  } else {
    listMastered.innerHTML = mastered.map(q => `<li><span class="q-id">${q.id}</span>${q.topic}</li>`).join("");
  }
  showScreen("screen-summary");
}

function initFlashcards() {
  const order = { critico: 0, alto: 1, medio: 2 };
  const sorted = [...QUESTIONS].sort((a,b) => order[a.priority] - order[b.priority]);
  const groups = { critico: [], alto: [], medio: [] };
  sorted.forEach(q => groups[q.priority].push(q));
  Object.values(groups).forEach(g => shuffle(g));
  state.flashcards.order = [...groups.critico, ...groups.alto, ...groups.medio];
  state.flashcards.index = 0;
  state.flashcards.revealed = false;
}

function renderFlashcard() {
  const fc = state.flashcards;
  const q = fc.order[fc.index];
  const p = getProgress(q.id);
  const body = $("#flashcard-body");

  $("#fc-current").textContent = fc.index + 1;
  $("#fc-total").textContent = fc.order.length;

  renderFlashcardDots();

  let statusHtml = "";
  if (p.mastered) statusHtml = '<span class="fc-status mastered">✓ Dominada</span>';
  else if (p.errCount > 0) statusHtml = '<span class="fc-status weak">⚠ Tema débil</span>';

  let html = `
    <div class="fc-tag">${q.id} · ${q.topic}</div>
    ${statusHtml}
    ${q.contexto ? `<div class="fc-context">${q.contexto}</div>` : ""}
    <div class="fc-question">${q.enunciado}</div>
  `;

  if (fc.revealed) {
    html += `
      <div class="fc-answer">
        <div class="feedback">
          <h4>Respuesta</h4>
          <div class="bloque">${q.respuestaLibre.replace(/\n/g, "<br>")}</div>
          <h4>Explicación</h4>
          <p>${q.explicacion}</p>
          <h4>Error típico</h4>
          <div class="error-tipico"><b>⚠</b> ${q.errorTipico}</div>
        </div>
        <div class="fc-self-eval">
          <button class="btn err" id="fc-costo">😕 Me costó</button>
          <button class="btn ok" id="fc-sabia">😊 La sabía</button>
        </div>
      </div>
    `;
  } else {
    html += `
      <div style="margin-top:auto;">
        <button class="btn" id="fc-reveal" style="width:100%; justify-content:center;">Mostrar respuesta</button>
      </div>
    `;
  }

  body.innerHTML = html;

  if (fc.revealed) {
    $("#fc-costo").addEventListener("click", () => handleFlashcardEval(q, false));
    $("#fc-sabia").addEventListener("click", () => handleFlashcardEval(q, true));
  } else {
    $("#fc-reveal").addEventListener("click", () => {
      state.flashcards.revealed = true;
      renderFlashcard();
    });
  }

  $("#fc-prev").disabled = fc.index === 0;
  $("#fc-next").disabled = fc.index === fc.order.length - 1;
}

function renderFlashcardDots() {
  const fc = state.flashcards;
  const dots = fc.order.map((q, i) => {
    const p = getProgress(q.id);
    let cls = "dot";
    if (i === fc.index) cls += " current";
    else if (p.mastered) cls += " mastered";
    else if (p.errCount > 0) cls += " weak";
    return `<div class="${cls}" title="${q.id}: ${q.topic}"></div>`;
  }).join("");
  $("#fc-dots").innerHTML = dots;
}

function handleFlashcardEval(q, knewIt) {
  const p = getProgress(q.id);
  p.attempts++;
  if (knewIt) {
    p.okCount++;
    state.sessionStats.ok++;
    if (p.okCount >= 2) p.mastered = true;
  } else {
    p.errCount++;
    state.sessionStats.err++;
    p.okCount = 0;
  }
  saveProgress();
  updateReviewOnlyButtonVisibility();

  const fc = state.flashcards;
  if (fc.index < fc.order.length - 1) {
    fc.index++;
    fc.revealed = false;
  } else {
    fc.revealed = false;
  }
  renderFlashcard();
}
